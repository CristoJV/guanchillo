# Architecture

Source files live in `src/guanchillo/`. The build compiles TypeScript to JavaScript and copies the HTML, CSS and icon into `dist/`. Relative imports in TypeScript use the emitted `.js` extension so browsers can load them directly.

| File | Responsibility |
| --- | --- |
| [index.html](../../src/guanchillo/index.html) and [styles.css](../../src/guanchillo/styles.css) | Native controls and responsive layout |
| [app.ts](../../src/guanchillo/app.ts) | View state, editor history, pattern library and crochet controls |
| [model.ts](../../src/guanchillo/model.ts) | Types, JSON validation and serialization, stitch order and color counts |
| [grid.ts](../../src/guanchillo/grid.ts) | Canvas layers, rulers, zoom and drag interpolation |
| [sphere.ts](../../src/guanchillo/sphere.ts) | Round sizes, shaping operations and six-gore projection |
| [globe.ts](../../src/guanchillo/globe.ts) and [earth.ts](../../src/guanchillo/earth.ts) | Rotatable sphere preview and Earth template |
| [storage.ts](../../src/guanchillo/storage.ts) | Browser storage and error reporting |

The grid uses a small color canvas scaled with CSS. A separate progress canvas can mark individual stitches. Sphere charts center each round across six gores and allow half-stitch shifts so even and odd widths stay centered. The 3D preview projects the same stitch colors onto a sphere from any angle. Painting updates the affected pixels during a drag. HTML controls and a live status region expose stitch position, color and progress.

## JSON format, version 1

A pattern can be written by hand, generated by another tool or exported from the editor. The example includes optional crochet progress.

```json
{
  "version": 1,
  "name": "Sample",
  "rows": 2,
  "cols": 2,
  "palette": [
    { "name": "Pine green", "hex": "#27574e" }
  ],
  "cells": [0, -1, 0, 0],
  "progress": {
    "version": 1,
    "rows": 2,
    "cols": 2,
    "row": 1,
    "col": 2,
    "direction": "rtl",
    "alternate": true,
    "offset": 2
  }
}
```

- Flat files omit `shape` and contain exactly `rows × cols` integers in `cells`. In any shape, read cells left to right and top to bottom. Values are zero-based palette indices, with `-1` for an unassigned stitch.
- Dimensions range from 1 to 256 per axis. The palette can have 1 to 24 colors. Names are 1 to 80 characters after trimming, and each color uses a six-digit hex code. Imports are limited to 1 MB.
- `progress.row` and `progress.col` are the starting point, counted from the bottom and left respectively. `direction` is `ltr` or `rtl`. When `alternate` is true, the direction flips on each subsequent row. `offset` counts finished stitches from that starting point. In the example, the two stitches in the bottom row are finished.
- When `progress` is absent, the imported pattern starts at the right edge of its first row or round. Existing version 1 pattern files remain compatible. Files with invalid progress are rejected before the library changes.
- An exported file includes an `id`. Imported copies receive a new local ID even when the file includes one.

`PatternFile`, `serializePattern` and `deserializePattern` define and implement the format in [model.ts](../../src/guanchillo/model.ts). The browser also stores patterns, progress and preferences as JSON.

### Sphere files

Set `"shape": "sphere"`. For `rows = 3n` (6 to 126 rounds), `cols = 6n` is the widest round. For round `r` counted from the bottom, the width is `6 × min(r, n, rows − r + 1)`. Store the rows' stitches from last round to first with no padding for projection gaps. Progress coordinates use the width of the starting round, and `alternate` is always `false`.

Shaping starts with six stitches in a magic ring, increases by six per shaping round, adds `n + 1` even rounds at the widest point, then decreases by six per round to close. The shaping repeats are staggered using Supergurumi's rounded variant. Each increase contributes two individually colorable stitches, while each decrease contributes one. [Supergurumi's sphere guide](https://www.supergurumi.com/es/tejer-esferas-y-bolas-de-cualquier-tamano)

## Browser storage

| Browser storage key | Content |
| --- | --- |
| `guanchillo:v1:pattern:<id>` | Pattern and ID |
| `guanchillo:v1:progress:<id>` | Current stitch path and completed count |
| `guanchillo:v1:preferences` | Active pattern and view |

Editor actions save after they finish. Crochet steps update the progress record as they happen. Resizing preserves the bottom-left corner of a flat grid and resamples spherical colors. Both changes reset the stitch path. Reads can fall back to keys created before the brand rename, and writes use the current prefix. Storage failures leave the working copy in memory and display an alert. When two tabs update the same record, the last write wins.
