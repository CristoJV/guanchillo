# Architecture

Source files live in `src/guanchillo/`. The build clears the generated `dist/` directory, compiles TypeScript to JavaScript and copies the static resources and indexed patterns. Relative imports in TypeScript use the emitted `.js` extension so browsers can load them directly.

| Module | Responsibility |
| --- | --- |
| [app.ts](../../src/guanchillo/app.ts) | Active pattern, session, navigation and JSON transfer |
| [core](../../src/guanchillo/core) | Pattern model and JSON validation, sphere geometry, template derivation, color math, stitch window and control bindings |
| [platform](../../src/guanchillo/platform) | Browser storage and loading the catalog manifest and patterns |
| [views/crochet](../../src/guanchillo/views/crochet) | Desktop chart tracking, mobile stitch strip, click and key routing, and crochet settings |
| [views/editor](../../src/guanchillo/views/editor) | Editor state and gestures, palette, pattern creation, and image import |
| [views/catalog](../../src/guanchillo/views/catalog) | Template cards, previews and filters |
| [views/library](../../src/guanchillo/views/library) | Local project search, progress summaries, and edit, resume and export actions |
| [views/shared](../../src/guanchillo/views/shared) | Canvas grid, sphere and flat previews, DOM helpers and compact layout breakpoint |

The editor and desktop crochet view share a canvas grid. A separate progress canvas marks completed stitches. Sphere charts center each round across six gores and allow half-stitch shifts so even and odd widths stay centered. Painting updates the affected pixels during a drag. A completed drag creates one undo entry. A canceled gesture restores the previous cells or reference position.

At widths up to 650 CSS pixels, the crochet view reserves three rows of up to eight stitches, centered on the current row or round. Neighboring sphere rounds show the corresponding portion of their circumference. Both views use the same current stitch and instruction. Stitch counts stop at a change in color or operation or at the end of the current row or round. Only the stitch that closes with the next yarn receives a color-change cue. The input controller routes background clicks, touch taps and keys in Crochet mode and leaves controls and dialogs to their normal event handling. The desktop chart uses primary clicks to jump to a stitch. The settings dialog also accepts row or round and stitch coordinates on the existing route. Its numbering follows the working direction.

The optional screen wake lock is requested while Crochet is visible and its route is unfinished. The browser can decline or revoke the request. Leaving Crochet, hiding the page or completing the route releases the lock. [W3C Screen Wake Lock API](https://www.w3.org/TR/screen-wake-lock/)

## JSON format, version 1

A pattern can be written by hand, generated by another tool or exported from the editor. The example includes optional crochet progress.

```json
{
  "version": 1,
  "name": "Sample",
  "rows": 2,
  "cols": 2,
  "shape": "flat",
  "recommended": { "rows": 2, "cols": 2 },
  "tags": ["example"],
  "palette": [
    { "name": "Pine green", "hex": "#27574e" }
  ],
  "cells": [0, -1, 0, 0],
  "progress": {
    "version": 1,
    "rows": 2,
    "cols": 2,
    "row": 1,
    "col": 2,
    "direction": "rtl",
    "alternate": true,
    "offset": 2
  }
}
```

- `shape` is `flat` or `sphere`. A flat file contains exactly `rows × cols` integers in `cells`. In either shape, read cells left to right and top to bottom. Values are zero-based palette indices, with `-1` for an unassigned stitch.
- `tags` is an array of lowercase labels using letters, numbers and hyphens, such as `sistema-solar`. Older files default to `flat` and an empty tag list when the fields are absent. An optional `source` object carries a `title`, an HTTPS `url` and an optional attribution `note`.
- Dimensions range from 1 to 256 per axis. New charts and image imports default to four colors and allow up to eight. Version 1 decoding also supports legacy palettes with up to 24 colors. Names are 1 to 80 characters after trimming, and each color uses a six-digit hex code. JSON imports and exports are limited to 1 MB.
- `colorProfiles` optionally defines smaller palettes for the same chart. Each profile has a `palette` of named colors and a `mapping` with one zero-based destination index per base palette entry. Profile palette sizes must be distinct and smaller than the base palette. Unassigned stitches remain unassigned.
- `recommended` gives the suggested size. It must fit within `rows` and `cols` and follow the sphere dimension rules for a sphere. Older files can omit it. Exports use the chart dimensions when no recommendation is stored.
- `progress.row` and `progress.col` are the starting point, counted from the bottom and left respectively. `direction` is `ltr` or `rtl`. When `alternate` is true, the direction flips on each subsequent row. `offset` counts finished stitches from that starting point. In the example, the two stitches in the bottom row are finished.
- The optional `progress.started` flag saves whether the countdown has been activated before the first stitch. Earlier records with a positive `offset` already count as started.
- When `progress` is absent, the imported pattern starts at the right edge of its first row or round. Existing version 1 pattern files remain compatible. Files with invalid progress are rejected before the library changes.
- An exported file includes an `id`. Imported copies receive a new local ID even when the file includes one.

`PatternFile` defines the format in [model.ts](../../src/guanchillo/core/model.ts). `serializePattern` and `deserializePattern` share a validator for the chart, metadata and optional crochet progress. The browser also stores patterns, progress and preferences as JSON.

### Sphere files

Set `"shape": "sphere"`. For `rows = 3n` (6 to 126 rounds), `cols = 6n` is the widest round. For round `r` counted from the bottom, the width is `6 × min(r, n, rows − r + 1)`. Store the rows' stitches from last round to first with no padding for projection gaps. Progress coordinates use the width of the starting round, and `alternate` is always `false`.

Shaping starts with six stitches in a magic ring, increases by six per shaping round, adds `n + 1` even rounds at the widest point, then decreases by six per round to close. The shaping repeats are staggered using Supergurumi's rounded variant. Each increase contributes two individually colorable stitches, while each decrease contributes one. [Supergurumi's sphere guide](https://www.supergurumi.com/es/tejer-esferas-y-bolas-de-cualquier-tamano)

## Templates and image conversion

[patterns/index.json](../../patterns/index.json) lists the published template filenames without their extensions in a `patterns` array. Each file stores one version 1 master chart with up to eight colors and explicit `shape` and `tags` metadata. Catalog builds both filter lists from that metadata and combines them with the name search. An intersection observer defers drawing previews until cards approach the viewport. Selecting a card action can resolve its variant independently of preview drawing. Sphere masters use 63 rounds and flat masters use up to 64 stitches along their longest side. The `recommended` field holds the default size, which may equal the master size. Give a chart a familiar theme tag only when it helps people find related patterns. Add another tag only when it supports a distinct search. Catalog shape is already a separate filter.

Catalog and New pattern derive each chart from its master. An exact color profile is applied before sampling. Smaller spheres choose the color with the greatest covered area across adjacent source rounds and stitches. Flat charts use nearest-neighbor sampling. When a profile is unavailable, similar colors are merged according to their stitch counts and color distance. Catalog keeps separate local records by dimensions and requested color count. Profiled variants have separate IDs so older saved copies can still be opened from the library. Optional master metadata in `variantRevisions` assigns positive revision numbers starting at 2 to specific color counts. A revised chart opens alongside older local copies. The metadata applies only to published templates. The build copies the indexed JSON files into `dist/patterns/`.

The 32 × 32 island charts are north-up adaptations of the generalized coastlines by Gobierno de Canarias and GRAFCAN, updated on 2020-09-08. Each island is fitted independently to the chart. [Generalized island data](https://datos.canarias.es/catalogos/general/dataset/islas-y-municipios/resource/7303b4c0-aaff-4189-9718-402eac0fa273), [SITCAN terms](https://opendata.sitcan.es/notice), [CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)

Image import downsamples a local image with Canvas. Automatic color selection uses weighted median cut on the downsampled pixels. A fixed palette maps each pixel to the closest chosen color. Transparency is represented by `-1`, just like an erased cell.

Design can also display the image beneath the color canvas as a local reference. The reference uses the image's original proportions and stores its offset in grid units so zoom preserves its alignment. References are scoped to a pattern for the lifetime of the page. Flat charts can fit their dimensions to the image within the row and column limits entered in the editor.

## Browser storage

| Browser storage key | Content |
| --- | --- |
| `guanchillo:v1:pattern:<id>` | Pattern and ID |
| `guanchillo:v1:progress:<id>` | Current stitch path and completed count |
| `guanchillo:v1:preferences` | Active pattern, view and optional screen wake preference. Legacy `collection` preferences open Catalog |
| `guanchillo:v1:crochet-controls` | Optional browser-wide key and mouse bindings for next and previous stitch |

Editor actions save after they finish. Crochet steps update the progress record as they happen. Resizing preserves the bottom-left corner of a flat grid and resamples spherical colors. Flat design scaling resamples the content and sets the new grid dimensions. Dimension changes reset the stitch path. Reads can fall back to keys created before the brand rename, and writes use the current prefix. Storage failures leave the working copy in memory and display an alert. When two tabs update the same record, the last write wins.
