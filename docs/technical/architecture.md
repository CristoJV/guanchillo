# Architecture

Source files live in `src/guanchillo/`. The build compiles TypeScript to JavaScript and copies the HTML, CSS and icon into `dist/`. Relative imports in TypeScript use the emitted `.js` extension so browsers can load them directly.

| File | Responsibility |
| --- | --- |
| [index.html](../../src/guanchillo/index.html) and [styles.css](../../src/guanchillo/styles.css) | Native controls and responsive layout |
| [app.ts](../../src/guanchillo/app.ts) | View state, editor history, pattern library and crochet controls |
| [model.ts](../../src/guanchillo/model.ts) | Types, JSON validation and serialization, stitch order and color counts |
| [grid.ts](../../src/guanchillo/grid.ts) | Canvas layers, rulers, zoom and drag interpolation |
| [storage.ts](../../src/guanchillo/storage.ts) | Browser storage and error reporting |

The color canvas uses one pixel per stitch. CSS handles scaling. The progress canvas uses a 3 × 3 pixel block per stitch so finished stitches can carry a center mark even when colors are similar. Painting updates the affected pixels during a drag. The editor commits the stroke as one undo action. HTML controls and a live status region expose cell position, color and progress to keyboard and screen reader users.

## JSON format, version 1

A pattern can be written by hand, generated by another tool or exported from the editor. The example includes optional crochet progress.

```json
{
  "version": 1,
  "name": "Sample",
  "rows": 2,
  "cols": 2,
  "palette": [
    { "name": "Pine green", "hex": "#27574e" }
  ],
  "cells": [0, -1, 0, 0],
  "progress": {
    "version": 1,
    "rows": 2,
    "cols": 2,
    "row": 1,
    "col": 2,
    "direction": "rtl",
    "alternate": true,
    "offset": 2
  }
}
```

- `cells` contains exactly `rows × cols` integers. Read them left to right and top to bottom. Values are zero-based palette indices, with `-1` for an unassigned stitch.
- Dimensions range from 1 to 256 per axis. The palette can have 1 to 24 colors. Names are 1 to 80 characters after trimming, and each color uses a six-digit hex code. Imports are limited to 1 MB.
- `progress.row` and `progress.col` are the starting point, counted from the bottom and left respectively. `direction` is `ltr` or `rtl`. When `alternate` is true, the direction flips on each subsequent row. `offset` counts finished stitches from that starting point. In the example, the two stitches in the bottom row are finished.
- When `progress` is absent, the imported pattern starts at the bottom right, moving right to left and alternating between rows. Existing version 1 pattern files remain compatible. Files with invalid progress are rejected before the library changes.
- An exported file includes an `id`. Imported copies receive a new local ID even when the file includes one.

`PatternFile`, `serializePattern` and `deserializePattern` define and implement the format in [model.ts](../../src/guanchillo/model.ts). The browser also stores patterns, progress and preferences as JSON.

| Browser storage key | Content |
| --- | --- |
| `ganchillo:v1:pattern:<id>` | Pattern and ID |
| `ganchillo:v1:progress:<id>` | Current stitch path and completed count |
| `ganchillo:v1:preferences` | Active pattern and view |

Editor actions save after they finish. Crochet steps update the progress record as they happen. Resizing preserves the bottom-left corner of the grid and resets the path. Storage failures leave the working copy in memory and display an alert. When two tabs update the same record, the last write wins.
